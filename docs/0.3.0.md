# LixinOS 0.3.0 · 双内核 rustc stage2 自举

Rust 内核和 TCC 内核分别用本机的 stage1 Cargo 和 rustc，从空的构建目录离线编译了 rustc 1.100.0。两次构建生成了逐字节相同的 AArch64 ELF，大小为 326,504,368 字节。编译器使用 Cranelift 0.135.9 后端。Cargo 保持在 stage1，两个构建都使用已安装的 Rust 标准库和 C SDK。

| QEMU 中的内核 | Cargo 记录的构建耗时 | 关机重启后的验证 |
| --- | --- | --- |
| Rust | 37 分 37 秒 | 用新生成的 rustc 编译并运行 Rust 2024 程序 |
| TCC | 36 分 52 秒 | 用新生成的 rustc 编译并运行同一程序 |

两边的测试都输出了 `stage2 verified`。把编译器安装到共享日常盘后，又分别启动两个内核，用 stage1 Cargo 指定对应的 stage2 rustc，在各自的空目标目录编译并运行同一个项目。两次都输出了 `daily stage2 passed`。

两份自举盘里，编译器的路径都是 `/stage2/rustc`。发布附件收录一份编译器和许可证。解包后，`rustc` 的 SHA-256 应为：

```text
fdafa2eb46c134e64ce05733002222670b240aefdd42836b68daa7e1415048e8
```

在已安装配套 Rust 标准库和 GCC 工具链的 LixinOS 构建盘上可以运行这个 ELF。种子工具链安装步骤、两块 stage2 盘的制作方法和 QEMU 复现命令见 [Rust 工具链说明](../User/rust/README.md#rebuild-rustc-with-stage1-on-each-kernel)。

本版支持让两个内核轮流使用同一个 4 GiB 日常盘。切换前在 Shell 输入 `q` 并回车，让当前内核完成写盘。配套双内核归档标签为 `kernel-2026-11-20.1`。已有日常盘按[共享盘迁移说明](../README.md#shell-and-disk)处理，恢复已归档内核见[回滚说明](kernel-releases.md)。
